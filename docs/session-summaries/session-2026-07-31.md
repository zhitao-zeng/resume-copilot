## 修复的 Bug

### 1. 文本 CV 提交必崩 — FileNameTooLong（`82be0c6`）

**现象**：`cv` 字段传纯文本时，`resume_generate_api.py:250` 拿整段 CV 文本（900+ 字符）当文件路径调 `_cv_text_path.exists()` → `os.stat` 抛 `OSError: [Errno 36] File name too long`。

**根因**：JSON/表单模式 fallback 逻辑无条件把 `cv_text` 当路径 stat，未做「看起来像路径」的守卫。

**附带发现**：`config/Dockerfile.v2-27b` **没有 COPY `resume_generate_api.py`**——镜像里一直是 base 镜像旧代码，本地改代码镜像不生效。已补 COPY 行。

**修复**：加 `_looks_like_path` 守卫（短、无换行、有扩展名才 stat）+ `try/except OSError`。

### 2. 文本 CV 被静默丢弃 — cv_upload=NONE（`82be0c6`）

**现象**：修好崩溃后，c1（有 924 字 CV）输出极空，仅 2 行 summary。日志显示 `cv_upload=NONE`，走了 No CV 路径。

**根因**：守卫修好后，`cv` 长文本既不满足路径条件也不传给 service——`cv_upload` 保持 None，CV 内容丢失。

**修复**：`cv` 为纯文本内容时，走内存 mock `_MockUpload(None, "cv.txt", content=cv_text)` 直接作为 CV 传给 pipeline。文件名必须带 `.txt` 后缀，否则 `_detect_extension` 返回空 → `ALLOWED_UPLOAD_EXTENSIONS` 校验 400 拒绝。

### 3. query 泄漏误删 CV 事实字段（`aabd594`，最关键）

**现象**：c39（散文式 CV，query 复述 CV 内容）渲染后 `education.school`、`experience.organization`、`project.name` 全空，但 pipeline 内部 DEBUG 显示数据正确。

**根因**：`_clean_template_watermarks` 的 `_is_query_leak` 在 `has_cv=True` 时，对「字段值是 query 子串」一律判定泄漏清除。c39 的 query 复述了自己 CV 的完整内容 → `school="北京邮电大学"` 恰好是 query 子串 → 被当 query 泄漏清空。**核心事实字段全灭**。

排查过程关键点：pipeline 内 DEBUG 数据正确（`edu_before/after` 都有学校名），说明问题不在提取/校验，而在渲染前的水印清理 stage。用本地模拟 `_clean_template_watermarks` 复现后定位。

**修复**：
- 核心事实字段（`.school`/`.organization`/`.institution`/`.degree`/`.major`/`.name`/`.role`/`.period`/`.company`）豁免 query 泄漏检查
- 字段值已存在于 CV 原文中的也豁免（CV 是事实来源，query 复述 CV 不算泄漏）
- 真正的 query 泄漏（描述性字段复制 query 文本）仍会被检测清除

### 4. education.school 空字段确定性回填（`c19aa34`）

**现象**：Composer 在散文式 CV（学校名出现在叙述句中）常漏填 `education.school`。

**修复**：`validate_resume` 增加 `source_text` 参数，school 空但 degree/major 非空时，从 summary（优先）/CV 原文正则提取学校名。正则 `(?:毕业于|就读于|就读|毕业|在|来自)?((?:(?!在|于|从)[一-龥]){2,8}(?:大学|学院))`：
- 排除「学校/中学」后缀（防匹配"没有学校"这类普通词）
- 排除 capture 内「在/于/从」（防叙述句动词混入学校名，如"毕业于上海交通大学"→"上海交通大学"）

## 测试过程中的坑

- `x-www-form-urlencoded` 提交不被 API 识别（只处理 multipart 和 JSON）→ 空输入卡 900s 超时，需用 multipart
- badcase 的 `cv_text` 是纯文本，不能直接当 `cv` 文件字段；`cv` 字段 multipart 文本会被 `_extract_file_field` Case 3 正确识别
- C1/C5/C39 全通过后才发现 C39 school 空——**必须解析 docx 内容验证，不能只看 ok=True**（那轮 6/6 ok 但内容有缺陷）
