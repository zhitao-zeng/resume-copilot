## 任务 1：RD1——电话号不得被数字守卫剥除

**现状：** `core/v3/numeric_guard.py` 的 `_RANGE_RE` 把 `189-2758-0370` 匹配成可疑年份
区间，事实被隔离、reply 报「数字/时间疑似识别错误」。真实用户丢联系方式。

- [ ] **步骤 1**：在 `_suspicion_reasons()` 判年份区间**之前**加电话形态豁免：
  中国手机（`1[3-9]\d{9}`，允许 `-`/空格/`.` 分隔成 3-4-4 等分组）、`+86` 前缀、
  座机（`0\d{2,3}[- ]?\d{7,8}`）。命中即非年份嫌疑，直接放行。
- [ ] **步骤 2**：电话所在事实应可被 meta 联系方式提取消费（若现有 meta 提取已覆盖，
  只需不隔离即可；勿顺手重写提取器）。
- [ ] **步骤 3**：测试 `tests/test_v3_numeric_guard.py`：
  `189-2758-0370`、`13812345678`、`+86 138 1234 5678`、`0755-8888 7777` → 不隔离；
  `204-2011`、`2019-2035`（>45 年跨度）→ 仍隔离（防回归，R25 的 OCR 年份场景不得放松）。

**验收：** own-zzt 重跑后电话出现在产出、`待确认数字` 为空；R25/R26 数字守卫测试零回归。

## 任务 2：md 结构适配器——嵌套语义 + 姓名 + 标记剥离（RD2/RD4-md/RD5）

**现状三断点**（trace 实证，2026-08-18）：`# 曾志涛` 整行消失；

## 任务 3：记录头形态识别（通用，非层级绑定）

**设计原则（回应"不同简历结构不一样"）：** 记录头不靠标题层级、不靠分隔符种类识别，
靠**内容形态**：一行同时满足 (a) 含时间区间锚点（复用现有 period 锚点检测）
(b) 短促非句子（无谓语句式、长度有界）→ 判为经历记录头，在当前章节内开 record。

- [ ] **步骤 1**：在 fact_graph 记录边界逻辑中加入形态判定（位置：现有
  "explicit structure > region > adjacency" 优先级链的 explicit 一档）。
- [ ] **步骤 2 分隔符 best-effort**：记录头行若可按 `｜`/`|`/`·`/`—` 等切成 2–3 段且
  其中一段是 period 锚点，则填 organization/role/period 字段；**切不出就整行作
  record 标签，不猜**。
- [ ] **步骤 3**：测试覆盖至少四种真实形态（`公司｜岗位｜时间`、`时间 公司 岗位`、
  `公司 - 岗位（时间）`、单独成行的公司+下一行时间），以及反例
  （含时间的正文长句 → 不得误判为记录头）。

**验收：** own-zzt 的公司/岗位/时间落在 experience record 字段上；dogfood 16 例
record 绑定率不降（对照 r0 的逐例 record 数）。
